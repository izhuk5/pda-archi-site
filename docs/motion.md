# Движение

Этот файл – библиотека приёмов и реестр того, что реализовано в `js/motion.js`. Значения (easing, длительности) живут в `styles/tokens.css`. Easing в GSAP – по имени токена без «--» (`ease: 'ease-sharp'`): `js/motion.js` регистрирует каждый `--ease-*` через CustomEase, строку `cubic-bezier()` GSAP не понимает. Решение, что и где движется, – в `docs/design-system.md`, «Принятые решения», пункт 5.

## Принципы
- Движение усиливает иерархию, а не украшает. Один громкий момент на страницу (обычно hero или пин-секция), остальное тихо.
- Появление по скроллу – один раз, при входе в 85 % высоты экрана. Не повторять при возврате.
- Всё уважает `prefers-reduced-motion` и режим `?static`: без анимаций страница полностью видна и свёрстана так же.
- Приём сначала описывается здесь, потом реализуется. В разметке – только имена из реестра.
- Не больше одной пин-секции на страницу и только если в ней есть что показывать по ходу прокрутки.
- Скролл – Lenis (`lerp` из `main.js`), якоря – через `lenis.scrollTo`. `scroll-behavior: smooth` в CSS не ставится.

## Штампы движения (см. TASTE.md, раздел 2)
Fade-up на каждом элементе; параллакс «потому что можно»; частицы на фоне; свечение за курсором; scramble-текст везде; пин на каждой второй секции; бесконечный марки без смысла. Каждый из них допустим только с одной фразой «зачем» в базе.

## Реестр `data-reveal`
Реализовано в `js/motion.js`. Параметры по умолчанию – в таблице, переопределения – через `data-reveal-delay`, `data-reveal-stagger`.

| Имя | Что делает | Параметры | Для чего |
|---|---|---|---|
| `fade` | появление из прозрачности с подъёмом на `--reveal-y` | 0.8 s, `--ease-out` | подписи, мелкие элементы |
| `lines` | строки текста выезжают из маски снизу (SplitText по строкам), маска снимается после | 0.9 s, шаг 0.08 | заголовки, абзацы |
| `chars` | буквы из маски строки снизу | 1 s, шаг 0.025 | один H1 |
| `clip` | окно раскрывается `clip-path` снизу вверх | 1 s, `--ease-sharp` | скриншоты, окна, фото |
| `card` | карточка всплывает снизу с лёгким масштабом, дети по очереди | 0.8 s, шаг 0.1 | карточки, стикеры |
| `stagger` | дети контейнера по очереди `fade` | шаг 0.08 | ленты, списки, чипы |
| `scrub` | прогресс твина привязан к прокрутке (без «один раз»), пишет `--p` (0…1) на элемент; в CSS – `var(--p, 0)` | `scrub: 1` | подсветка слов, поворот стикера, прогресс сцены |

Приёмы, которых здесь нет, – не существуют. Нужен новый – скилл `motion`. `npm run check` сверяет эту таблицу с `PRESETS` в `js/motion.js` в обе стороны.

## Hover
Hover описывается как приём с именем и токенами: что меняется, за сколько, с каким easing. Смена цвета фона у кнопки – не приём, а дефолт.

## Как проверять
- `?static` – всё видно, ничего не движется: так снимаются скриншоты.
- В обычном режиме – несколько скриншотов подряд для время-зависимых состояний.
- Во встроенном браузере Claude при скрытой панели rAF стоит: проверять состояние через `gsap.getProperty` и `gsap.ticker.tick()` вручную.
- Пин-секция: скроллом до конца и обратно, проверить, что ничего не осталось «залипшим».
