# Движение

Этот файл – библиотека приёмов и реестр того, что реализовано в `src/lib/motion.js`. Значения (easing, длительности) живут в `src/styles/tokens.css`. Easing в GSAP – по имени токена без «--» (`ease: 'ease-sharp'`): `src/lib/motion.js` регистрирует каждый `--ease-*` через CustomEase, строку `cubic-bezier()` GSAP не понимает. Решение, что и где движется, – в `docs/design-system.md`, «Принятые решения», пункт 5.

Где живёт код: GSAP и плагины – только `src/lib/gsap.js` (импорт и регистрация один раз), реестр появления `data-reveal` – `src/lib/motion.js`, приёмы одной секции (пин, scrub, hover, своя таймлиния) – её `<имя>.js` внутри `onMotion()` из `src/lib/env.js`. Приём, которого нет в этом файле, не существует – ни в реестре, ни в JS секции.

Два уровня условий:
- **Включено ли движение вообще** – один раз при загрузке: inline-скрипт в `<head>` (`src/layouts/base.astro`) ставит `html.has-motion`, `env.js` читает его как `motionOn`, `onMotion()` запускает JS секции только при нём. Отвечает за `data-reveal`, Lenis и 3D.
- **Условия внутри секции** – `gsap.matchMedia()`: брейкпоинты (пин transformation только от 768 – `transformation.js`) и reduced-motion, если секции нужен свой вариант, а не «ничего»: `mm.add({ isDesktop: '(min-width: 768px)', reduce: '(prefers-reduced-motion: reduce)' }, ctx => { … })`. matchMedia сам откатывает твины и ScrollTrigger при смене условия, в том числе при переключении reduced-motion на открытой странице.
- Грабля: `onMotion()` при reduced-motion не вызывает функцию вовсе – ветка `reduce` внутри него не сработает. Секция со своим вариантом для reduced-motion ставит `gsap.matchMedia()` вне `onMotion()` и сама проверяет `isStatic` из `env.js`; приём с таким вариантом описывается здесь.

## Принципы
- Движение усиливает иерархию, а не украшает. Один громкий момент на страницу (обычно hero или пин-секция), остальное тихо.
- Появление по скроллу – один раз, при входе в 85 % высоты экрана, точка запуска ограничена концом прокрутки (`clamp()`), иначе элементы у конца страницы не появляются. Не повторять при возврате. Исключение – элементы, видимые уже при загрузке (первый экран): они появляются сразу, не дожидаясь прокрутки (`inFirstScreen` в `src/lib/motion.js`).
- Подготовка появления – ленивая (`initMotion`, `src/lib/motion.js`): элементы первого экрана режутся и получают стартовое состояние сразу, остальные – когда до них полтора экрана (`IntersectionObserver`). Замеры – одним проходом до записи в DOM. `ScrollTrigger.sort()` + `refresh()` – один раз в конце `initMotion`; секции после создания пина `refresh()` не вызывают (их `onMotion()` выполняется раньше – скрипты секций стоят в HTML до `base.astro`). Причина – Lighthouse «forced reflow»: при подготовке всех 32 элементов разом – 173 принудительных пересчёта раскладки при загрузке, стало ~100.
- Всё уважает `prefers-reduced-motion` и режим `?static`: без анимаций страница полностью видна и свёрстана так же.
- Приём сначала описывается здесь, потом реализуется. В разметке – только имена из реестра.
- Не больше одной пин-секции на страницу и только если в ней есть что показывать по ходу прокрутки. Исключение по решению пользователя (2026-10-01): `transformation` и `digital-lab` – две пин-секции.
- Скролл – Lenis (`lerp` из `main.js`), якоря – через `lenis.scrollTo`. `scroll-behavior: smooth` в CSS не ставится.

## Штампы движения (см. TASTE.md, раздел 2)
Fade-up на каждом элементе; параллакс «потому что можно»; частицы на фоне; свечение за курсором; scramble-текст везде; пин на каждой второй секции; бесконечный марки без смысла. Каждый из них допустим только с одной фразой «зачем» в базе.

## Реестр `data-reveal`
Реализовано в `src/lib/motion.js`. Параметры по умолчанию – в таблице, переопределения – через `data-reveal-delay`, `data-reveal-stagger`.

| Имя | Что делает | Параметры | Для чего |
|---|---|---|---|
| `fade` | появление из прозрачности с подъёмом на `--reveal-y` | 0.8 s, `power3.out` (как на старом сайте; не `--ease-out`) | подписи, мелкие элементы |
| `lines` | строки текста выезжают из маски снизу (SplitText по строкам), маска снимается после | 0.9 s, шаг 0.08 | заголовки, абзацы |
| `words` | слова по одному выезжают из маски своей строки (`yPercent` 101 → 0), маска снимается после. Замер kononenkogroup.com («Systematic Clarity & Creativity»): кривая экспоненциальная, остаток пути × 0.8 каждые 50 мс – это `expo.out` 1.55 s, слово отстаёт от предыдущего на 100 мс. Маска строки шире строки на `--mask-bleed` сверху и снизу – при интерлиньяже 0.7 иначе режутся выносные | 1.55 s `expo.out`, шаг 0.1 | заявление about |
| `chars` | буквы из маски строки снизу | 1 s, шаг 0.025 | один H1 (на странице не используется) |
| `letters` | буквы знака поднимаются снизу по одной: каждая начинает с `y` = 105 % высоты знака, край знака (`overflow: clip`) – маска; после появления разбивка снимается. Повтор замера kononenkogroup.com (KNKO в подвале): шаг 65 мс, `expo.out`; длительность подобрана сравнением кривых – 1.6 s, старт при верхе знака на 75 % экрана, один раз | 1.6 s `expo.out`, шаг 0.065, `clamp(top 75%)` | гигантский знак PDA в подвале |
| `clip` | окно раскрывается `clip-path` снизу вверх: сразу и с плавным торможением. Не `--ease-sharp`: на старом сайте стояла строка `cubic-bezier()`, GSAP её не понимал и брал `power1.out` – так фото и были утверждены; настоящий `--ease-sharp` (медленный старт, рывок посередине) пользователь назвал резким, замер 2026-10-04: 7 % за 300 мс, затем 17 → 63 % за 100 мс | 1 s, `power1.out` | фото проектов |
| `card` | карточка всплывает снизу с лёгким масштабом, дети по очереди | 0.8 s, шаг 0.1 | карточки, стикеры (на странице не используется) |
| `stagger` | дети контейнера по очереди `fade` | шаг 0.08 | короткие списки: факты about, строки expertise |
| `rows` | длинный список: каждая строка появляется сама, когда её верх проходит 92 % экрана (`ScrollTrigger.batch`), строки одной порции – с шагом | 0.7 s `power3.out`, шаг 0.06 | списки длиннее экрана: clients. `stagger` анимировал все дети разом по верху списка – нижние строки проявлялись невидимыми или ждали прокрутки |
| `photo-in` | фото проявляется из фона страницы и чуть уменьшается (масштаб 1.06 → 1); вместе с ним проявляется затемнение секции через переменную `--photo-in` (0 → 1) на ближайшей `section`. Стартует, когда картинка декодирована | 1.4 s, `power2.out` | фото hero при загрузке, как у kononenkogroup.com без прелоадера. Текст hero приходит после фото через `data-reveal-delay` |
| `scrub` | прогресс твина привязан к прокрутке (без «один раз»), пишет `--p` (0…1) на элемент; в CSS – `var(--p, 0)`. Параллакс фото – не отдельный приём: `scrub` на секции или рамке даёт `--p`, правило секции сдвигает фото свойством `translate` (не `transform`: GSAP пишет элементам с твинами `translate: none`). Фото hero отстаёт на 20 % прокрутки (`--parallax-hero`); фото в рамке (about) выше рамки на `--parallax-extra` и проходит её от края до края | `scrub: 1` | параллакс фото hero и about, как у kononenkogroup.com. Штамп «параллакс потому что можно» оправдан: просьба пользователя и главный приём референса, только крупные фото, не карточки |

Приёмы, которых здесь нет, – не существуют. Нужен новый – скилл `motion`. `npm run check` сверяет эту таблицу с `PRESETS` в `src/lib/motion.js` в обе стороны.

## Приёмы секций
Не `data-reveal`, а JS своей секции или компонента (`<имя>.js`, внутри `onMotion()`). Описаны по старому сайту (wow-site-starter); код переносится вместе с секцией, файл – в колонке «Где».

| Имя | Что делает | Параметры | Где |
|---|---|---|---|
| `compare-pin` | пин-секция «было – стало». Секция закрепляется, в каждой главе шторка по скроллу: переменная `--split` 100 % → 0 %, слева «до», справа открывается «после», пауза 0.25 доли главы. Смена главы: кадр следующей главы открывается снизу поверх предыдущего (`clip-path` 100 % → 0, 0.4 доли главы, фото внутри 1.15 → 1) – по скроллу; текст главы меняется по времени, когда скролл пересекает границу главы: строки уходят под маску вверх (0.5 s `power3.in`, шаг 0.03), новые выезжают снизу (0.9 s `power4.out`, шаг 0.06, задержка 0.3 s), при обратном скролле направления меняются; подпись кадра гаснет и проявляется. Внизу слева счётчик «1 / 3» и линия прогресса (переменная `--tr-p`). Глава считается в `onUpdate` таймлайна, а не ScrollTrigger. С пином у главы строка сетки `minmax(0, 1fr)`, кадр по высоте экрана (баг 2026-10-04: на 1920 × 960 текст заезжал под счётчик). Только от 768 px (`gsap.matchMedia`); телефон, `?static`, reduced motion – главы стопкой со шторкой пальцем (`compare`). После создания пина – `ScrollTrigger.sort()` и `refresh()`: появления ниже по странице созданы в другом модуле и без сортировки не учли бы прокрутку пина | `scrub: 1`, 1 экран прокрутки на главу; текст – время, не скролл | `transformation.js`. Фирменный приём: прокрутка двигает время в здании |
| `h-scroll` | горизонтальная лента: на любой ширине (на телефоне тоже – решение пользователя 2026-10-04) секция закрепляется, вертикальная прокрутка сдвигает ленту по X на её лишнюю ширину (`scrollWidth − ширина окна`). Внутри ленты через `containerAnimation`: фото и чертежи сдвигаются в кадре на ±`--parallax-x` % при увеличении `--parallax-zoom` (масштаб – в том же твине, GSAP перезаписывает CSS `scale`); номер, название и текст шага проявляются с подъёмом при входе шага на 85 % ширины. Счётчика и линии прогресса нет. Без движения (`?static`, reduced-motion) – нативная прокрутка ленты со `scroll-snap`. Триггер параллакса – рамка `.digital-lab-figure`, а не родитель картинки (у `<picture>` из Photo нет своего блока). После создания пина – `ScrollTrigger.sort()` и `refresh()`, как у `compare-pin` | лента `scrub: 1`; параллакс `scrub: true`; текст 0.8 s `power3.out`, шаг 0.08 | `digital-lab.js`. Вторая пин-секция – исключение, решение пользователя 2026-10-01 |
| `header-blend` | закреплённая шапка: у самого верха страницы – белая (`mix-blend-mode: normal`, над фото hero), после прокрутки на треть экрана – `mix-blend-mode: difference`: чёрная на светлом, белая на тёмном. Повтор референса (класс переключается около 300 px на экране 900) | порог `innerHeight / 3` – ScrollTrigger со `start` числом; смешивание не анимируется | `header.js` |
| `header-hide` | когда подвал закрыл экран, строки шапки уходят вверх под маску все разом (`yPercent` 0 → −100) и клики выключаются; при прокрутке обратно возвращаются снизу по одной – три строки имени, затем ссылки меню слева направо. Так же строки появляются при загрузке вместе со входом hero. Замер референса по каждой из 7 строк: скрытие без шага, появление с шагом 100 мс | скрытие 1.3 s `power4.out`; появление 1.55 s `power4.out`, шаг 0.1; при загрузке – задержка 1.1 s, и только если шапка не скрыта (страница открыта у подвала – входа нет, иначе вход и скрытие спорят за строки) | `header.js`; без движения – шапка просто скрывается |

## Hover и жесты
Hover описывается как приём с именем и токенами: что меняется, за сколько, с каким easing. Смена цвета фона у кнопки – не приём, а дефолт.

| Имя | Что делает | Параметры | Где |
|---|---|---|---|
| `card-zoom` | фото карточки увеличивается внутри рамки (CSS `scale`, рамка режет края) | `--hover-zoom` 1.03, `--dur-600`, `--ease-out` | карточки проектов |
| `accordion` (жест) | строка-аккордеон раскрывается (на тач-экране – только высота панели, текст не анимируется: `gsap.matchMedia('(hover: hover) and (pointer: fine)')` в `expertise.js`): высота панели 0 → auto, затем дети панели по очереди проявляются с подъёмом на `--reveal-y`; закрытие – дети гаснут, высота → 0. Открыта одна строка: при открытии другая закрывается одновременно. Если закрывается строка выше кликнутой, на время анимации (1 s) прокрутка компенсирует сдвиг кадр за кадром (через Lenis без сглаживания) – кликнутая строка остаётся под курсором; без движения – одной поправкой сразу. Двойной и тройной клик по строке не выделяет текст. Знак «+» поворачивается на `--sign-turn` в «×» (CSS-переход по классу `is-open`, не GSAP – грабля про SVG и rotation) | высота 0.6 s `power3.inOut`; дети 0.5 s `power3.out`, шаг 0.06, старт с 0.25 s; знак `--dur-600`, `--ease-out`. При reduced motion и `?static` – без длительности | строки expertise, `expertise.js` |
| `link-line` | линия под ссылкой – фон-градиент высотой `--link-line`, растёт по ширине. В меню и подвале: в покое нет, при наведении растёт слева направо, при уходе уезжает вправо. Ссылка в тексте и активная: видна, при наведении уезжает вправо, после – возвращается слева. Замер kononenkogroup.com: 1.109 s, кривая `--ease-link`, точка роста меняется слева/справа | `--dur-link`, `--ease-link` | все текстовые ссылки |
| `row-shift` | название строки сдвигается вправо на `--row-shift`, знак – на ту же величину влево. В expertise – только при `(hover: hover) and (pointer: fine)`: на тач-экране тап залипает в `:hover`, и заголовок уезжал при открытии | `--dur-600`, `--ease-out` | строки expertise, clients, контакты |
| `thumb-reveal` | обложка проекта в строке клиента открывается сверху вниз (`clip-path`) при наведении мышью (`(hover: hover) and (pointer: fine)`; на тач-экране – `row-active`); вместе с `row-shift` у названия. Строка не кликается (окон проектов нет) – обложка просто показывает проект | `--dur-600`, `--ease-out` | строки clients |
| `row-active` (скролл) | тач-версия `row-shift` + `thumb-reveal`: строка, которая пересекает линию 55 % высоты экрана, получает класс `is-active` – название сдвигается, обложка раскрывается, как при наведении; ушла с линии – закрывается. Только на тач-экранах (`(hover: none), (pointer: coarse)` через `gsap.matchMedia()` в `clients.js`), внутри `onMotion()`. Без движения на тач-экране обложки открыты сразу. Место под обложку на телефоне зарезервировано – строка при раскрытии не меняет высоту | ScrollTrigger `toggleClass`, без scrub; длительность и easing – те же `--dur-600`, `--ease-out` (CSS transition) | строки clients на тач-экранах |
| `fill-up` | кнопка: фон заливается снизу вверх (`background-size` 0 → 100 %), текст меняет цвет | `--dur-600`, `--ease-out` | кнопка формы contact |
| `compare` (жест) | шторка «до / после» двигается пальцем или мышью: прозрачный `input type="range"` поверх кадра пишет переменную `--split`; клавиатура – стрелки | без длительности, следует за пальцем | компонент `Compare` в transformation; в пин-режиме ползунок скрыт, шторку ведёт прокрутка |

## Как проверять
- `?static` – всё видно, ничего не движется: так снимаются скриншоты.
- В обычном режиме – несколько скриншотов подряд для время-зависимых состояний.
- Во встроенном браузере Claude при скрытой панели rAF стоит: проверять состояние через `gsap.getProperty` и `gsap.ticker.tick()` вручную.
- Пин-секция: скроллом до конца и обратно, проверить, что ничего не осталось «залипшим». Пин проверять и в широком низком окне (1920 × 960), не только 1440 × 900.
