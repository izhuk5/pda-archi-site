# Критика по TASTE.md

Не перестраивать. Только диагноз. Формат каждого замечания: что – почему важно (одна строка) – как исправить. Каждое замечание – с селектором, файлом и строкой, измеренными числами (кегль, отступ, контраст, интерлиньяж), а не впечатлением.

1. Открыть `docs/TASTE.md` целиком и «Принятые решения» из `docs/design-system.md`.
2. Снять скриншот 390 и 1440 (`npm run shot -- <id>`), смотреть на картинку, а не на разметку.
3. Ответить письменно на три вопроса раздела 4:
   - что здесь можно было сделать для любого другого продукта;
   - где фирменный приём, или секция осознанно тихая;
   - какие штампы из раздела 2 использованы и чем оправданы.
4. Пройти список «Лишние детали»: сколько текстовых и графических элементов в блоке против сущностей в задаче. Лишние – назвать.
5. Движение и 3D: есть ли элемент, который движется без приёма из `docs/motion.md`; есть ли сцена без строки в решениях.
6. Итог: три самых важных правки в порядке влияния. Не больше трёх в первом заходе.

Для свежего взгляда критику можно поручить субагенту `critic` – у него нет контекста сборки и он не оправдывает свои решения.
