## 2026-10-05 – Lighthouse: forced reflow
- Проход скиллом gsap-performance по просьбе пользователя. Диагноз трассой Chrome на dev-сервере (CPU ×4, стеки): основная часть – подготовка всех 32 появлений при загрузке (GSAP читает стили посреди записи, SplitText мерит строки, ScrollTrigger мерит триггеры), плюс три полных `ScrollTrigger.refresh()` подряд и замер «первый экран» после записи.
- Сделано: ленивая подготовка появлений (`IntersectionObserver`, запас полтора экрана), замеры одним проходом до записи, один `sort()` + `refresh()` в конце `initMotion`. Не сработало и откачено: «прогрев» кеша transform через `gsap.getProperty` – пересчётов стало больше (183).
- Итог: 173 → ~100 пересчётов, 34 → 22 мс, длинные задачи при загрузке почти ушли. Остаток – внутри SplitText и ScrollTrigger при подготовке первого экрана, это их работа.

## 2026-10-04 – картинки в AVIF, компонент Photo
- Решение пользователя: картинки в AVIF. В Astro, в отличие от `next/image`, нет сервера, который подбирает формат на лету: форматы готовятся при сборке, а выбирает браузер по `<source type>`. Общей настройки «всё в AVIF» нет – поэтому свой компонент `Photo` на `getImage()`: AVIF, затем WebP, затем JPG. `<Picture>` из Astro не взят: он не умеет свой кадр для телефона (hero, about).
- Вес картинок в сборке: AVIF 4,5 МБ против 8,4 МБ WebP (–46 %); браузер с поддержкой AVIF (все актуальные) качает только AVIF. Сборка – 16 s.
- Линтер: `<img>` разрешён только внутри `src/components/photo/`, `Photo` без `alt` – замечание (проверено вставкой).
- Грабля: у `<picture>` с `display: contents` пустые `<source>` становятся ячейками сетки родителя – `picture > source { display: none }` в base.css.
- Проверка: вёрстка до и после – 474 элемента, отличий 0 на 1440 и 390; Chrome грузит AVIF для всех 32 картинок, на 390 – мобильные кадры hero и about; проход по странице с движением – 0 ошибок. `npm run check` – 0.
